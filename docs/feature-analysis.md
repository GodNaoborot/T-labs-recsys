# Что содержится в автоматическом наборе признаков

Посмотрим, какие признаки вошли в **автоматический набор из 462 формул**.
Важности взяты из итогового ранкера `D462-t`.

Самая высокая отдельная важность получилась у времени после последнего
доступного события пользователя: **14.21**. Также используются недавние метки
пользователя и история пары пользователь–трек. В набор вошли все окна
от 1 до 30 дней.

## Откуда взялись 462 признака

В исходном поиске было **12 782 кандидата**: по 3 195 формул для четырёх
сущностей и два контекстных поля. Грамматика включает статистики по всей
доступной истории, окна 1–30 дней, произведения и давности. Произведения
агрегатов строятся внутри одного окна.

Первый отбор на небольшой выборке не нашёл сокращённый top-k, который
превзошёл бы полный набор. Затем из обученной на всех кандидатах модели
сохранили признаки, встречавшиеся в её разбиениях. Так получился список 462;
он зафиксирован в `temporal_used_20261023_v1/protocol.json`.

Этот список был получен **в прежнем протоколе с восстановленным временем**.
В основном сравнении его перенесли без нового отбора и заново рассчитали
значения по исправленной истории.

Среди выбранных 462 входов **нет отдельных контекстных полей текущего события**
`is_organic` и `track_length_seconds`. Они были среди кандидатов, но не вошли
в этот список как самостоятельные входы. Они встречаются внутри
исторических агрегатов; ручные наборы используют и текущие значения.

## Какие операции используются

Каждая формула отнесена к одному из четырёх видов:

| Вид формулы | Количество | Сумма важностей |
| --- | ---: | ---: |
| Один агрегат: count, mean, min, max или std | 52 | 18.97 |
| Произведение двух агрегатов | 349 | 56.64 |
| Агрегат произведения полей исторического события | 56 | 6.66 |
| Давность первого или последнего события | 5 | 17.73 |

Например, `MEAN(label * track_length_seconds)` сначала умножает два поля
каждого исторического события, а затем усредняет. Формула
`MEAN(label) * MEAN(track_length_seconds)` сначала считает два средних и
умножает их. Это разные признаки.

По отдельным агрегатам есть ещё [primitive_counts.csv](results/feature-analysis/primitive_counts.csv).
В нём формула с `MAX * MEAN` учитывается и у MAX, и у MEAN, поэтому сумма
чисел не равна 462. Общие виды формул: [operation_summary.csv](results/feature-analysis/operation_summary.csv).

## Что получилось с временными окнами

**51 формула** использует всю доступную историю, включая пять давностей.
Оставшиеся **411** используют ограниченное окно. В выбранном наборе
представлены все длины от 1 до 30 дней.

| История / окно | Формул | Сумма важностей |
| --- | ---: | ---: |
| Вся доступная история | 51 | 38.55 |
| 1 день | 38 | 18.92 |
| 2 дня | 29 | 7.38 |
| 3 дня | 22 | 5.86 |
| Остальные окна 4–30 дней | 322 | 29.28 |

У окон 1–3 дня суммарная важность составила **32.16**. Важны и признаки
всей истории: модель использует короткие и длинные горизонты вместе.
Соседние окна пересекаются, поэтому такая таблица не показывает качество
моделей, в которых менялась бы только длина окна.

Все 30 окон: [window_summary.csv](results/feature-analysis/window_summary.csv).
Для каждого запроса с моментом `t` история строго раньше `t`, а окно имеет
вид `[t - window, t)`. Процент текущего прослушивания не задаёт эту границу.

## Несколько формул простыми словами

В следующей таблице `label` всегда относится к **историческим** событиям,
доступным до `t`. Это эвристические метки 0/1/2, а не вероятность лайка.

| Формула из готовой модели | Смысл | Важность |
| --- | --- | ---: |
| `Users__TIME_SINCE_LAST(...)` | Сколько дней прошло с последнего доступного события пользователя | 14.21 |
| `Users__MAX(label, 1d) * MEAN(label, 1d)` | Произведение максимальной и средней исторической метки пользователя за сутки | 7.03 |
| `UserItem__MEAN(label)` | Средняя историческая метка этой пары пользователь–трек | 6.71 |
| `Users__MEAN(label, 3d)` | Средняя метка пользователя за последние три дня | 3.64 |
| `Users__COUNT(2d) * MEAN(label, 2d)` | Число событий за двое суток, умноженное на их среднюю метку | 2.01 |
| `UserItem__TIME_SINCE_FIRST(...)` | Сколько дней прошло с первого доступного взаимодействия этой пары | 1.13 |
| `Users__MEAN(label * track_length_seconds, 4d)` | Среднее произведение исторической метки и длины трека за четыре дня | 1.04 |

При непустой истории `COUNT * MEAN(label)` равен сумме меток. Получается,
что сочетание простых операций выражает SUM, хотя отдельного такого примитива
не было. Для пустой истории результат зависит от обработки NaN.

Полные имена и пояснения двадцати первых формул: [top_features.csv](results/feature-analysis/top_features.csv).

## Как понимать важности

Здесь используется **CatBoost PredictionValuesChange** из сохранённого отчёта
`models/D462-t/evaluation.json`. Значения нормированы до суммы 100 и описывают
изменения предсказаний готовой модели. Вклад в качество по ним не измеряется.

У 453 из 462 входов важность положительна, у девяти равна нулю. Число 462
задаёт перенесённый список входов; девять нулевых признаков в нём оставлены.

## Как проверить отчёт

Итоговый ноутбук читает только небольшие готовые CSV. Для просмотра разбора
не нужны модели, матрицы или полный датасет.

Пересобрать таблицы из опубликованных описаний формул и копии уже
сохранённых важностей можно из корня проекта:

```bash
python task_1/src/summarize_selected_features.py
```

Скрипту достаточно стандартной библиотеки Python. Он сверяет порядок
462 входов, хеши определений и имена из CSV важностей. JSON Featuretools
читается как дерево операций; сами значения признаков не пересчитываются.

Происхождение и SHA256 всех источников и выходных CSV:
[provenance.json](results/feature-analysis/provenance.json).
Полный список входов с индексом столбца, видом операции, окном и пояснением:
[selected_features.csv](results/feature-analysis/selected_features.csv).
Копия исходных важностей:
[prediction_values_change.csv](results/feature-analysis/prediction_values_change.csv).
